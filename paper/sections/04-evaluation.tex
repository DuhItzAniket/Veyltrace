\section{Evaluation Setup}
\label{sec:eval}

We fixed the research questions, hypotheses, datasets, splits, methods, metrics, statistical tests and reporting rules before running any \sys arm on a test split.
The protocol, the Reason-lane engine configurations (core, FaultLoom, Causatrix and Causentra) and the 55 experiment configurations marked as pre-registered are frozen at the git tag \code{prereg-v1} (annotated on 18 November 2026), following a pre-registered RCAEval study, posted as a preprint, that tagged a commit before seeing any fault window~\cite{hussain2026prereg}.
Before the tag we ran only baseline reproduction on RE2, development on synthetic cases and RE1, and three development cases, one per RE2 system, which are excluded from every test table.
Any later change to a frozen file is a logged deviation; if one is motivated by test results, we report both the pre-registered and the revised numbers.
Section~\ref{sec:deviations} lists every logged deviation and every pre-registered experiment that was cut.
Every number in Section~\ref{sec:results} traces from a generated table to a summary file, its manifest, a committed experiment configuration and a clean code commit.

\subsection{Datasets}
\label{sec:datasets}

\emph{RCAEval}~\cite{rcaeval2024} is our anchor.
Its RE2 suite has 270 cases, 90 for each of Online Boutique (OB), Sock Shop (SS) and Train Ticket (TT): six fault types (CPU, memory, disk, socket, delay and loss), each injected into five services three times, with metrics and logs for every system and traces only for OB and TT.
RE3 adds 90 cases with code-level faults, and RE1 (375 metric-only cases) is the only real data on which a value may be tuned; two broken RE1-OB cases are excluded.
Ground truth is the case folder name, from which the benchmark harness derives an answer key that no engine can read; engines see only an opaque case identifier.
Because RCAEval injects faults into only five services per system, a ranker that reads no telemetry reaches an Avg@5 of 0.488 on held-out incidents~\cite{buljic2026prior}, which is why we report AC@1, lift over chance and, on RE2 and RE3, a prior-only floor.
\emph{RCAEval-C} adds synthetic change events to RE2 (\S\ref{sec:protocols}); \emph{normal windows} are pre-injection segments of RE2 cases (\S\ref{sec:splits}).
Nezha~\cite{nezha2023} (101 cases on OB and TT, with metrics, logs and traces) is pre-registered as a cross-source check; its ingest adapter is part of the engine-freeze commit, and Nezha is reported with the proposer off only (\S\ref{sec:deviations}).
VeylLab, our laptop-collected dataset with real deploy, configuration and flag events and no-fault controls, was pre-registered where it reaches its target size; it did not (8 of 120 captures, and no ingest adapter), and both VeylLab experiments are cut.
No result in this paper therefore uses real change events; RCAEval-C's changes are synthetic.
The propagation-aware Train Ticket set of Fang et al.~\cite{fang2026rethinking} was pre-registered as a stretch dataset and is cut, because its size, format and licence were not verified.
A pre-registered dataset or arm that cannot run is reported as not run, with its reason and the decision record that cut it (Appendix~\ref{sec:appendix}).
Five synthetic cases serve only as continuous-integration fixtures and are never reported.

\subsection{Methods and baselines}
\label{sec:baselines}

All methods run in one harness, on the same cases, inputs and alert times, in one pinned environment, and we never mix published numbers into our tables.
The honest floors are chance, reported as a metric of every group, and \code{prior-only}, which ranks services by how often they are the root in the calibration fold and reads no telemetry; floors are shown in every accuracy table (\code{prior-only} on RE2 and RE3 only, chance everywhere) but are not candidates for the comparisons below.
N-Sigma and BARO run from RCAEval's own code at tag 1.12.0 in an isolated environment and receive the same alert time as \sys.
In this harness, RCAEval's BARO reproduces the RE2-TT results published with the benchmark~\cite{rcaeval2024} to two decimals: AC@1 \resnum{re2-oracle-baselines-r05}{tt/rcaeval:baro/ac_at_1}, AC@3 \resnum{re2-oracle-baselines-r05}{tt/rcaeval:baro/ac_at_k.ac_at_3} and Avg@5 \resnum{re2-oracle-baselines-r05}{tt/rcaeval:baro/avg_at_5} (experiment \code{re2-oracle-}\allowbreak\code{baselines-r05}, the baseline-reproduction run made before the tag: not pre-registered, on all 270 RE2 cases including the development cases, in an older summary format).
\code{simplerca} is our re-implementation of the alert-count baseline of Fang et al.~\cite{fang2026rethinking}, which ranks services by the number of metric, trace and log alerts.
The \emph{best reproduced simple baseline} of H1a and H1b is whichever of \code{rcaeval:nsigma}, \code{rcaeval:baro} and \code{simplerca} has the highest AC@1 on the same evaluation cases, chosen per system for H1a and pooled over RE2 for H1b; choosing it on the test cases favours the baseline.
Each Causatrix ranker alone (\code{causatrix:<ranker>}) and the fused slate without the verifier (\code{causatrix:rrf}) are ablations.
The \sys arms are \code{veyltrace:off}; \code{veyltrace:brief}, with the proposer in its one- or two-call mode over evidence cards and the verifier on, run with three seeds; \code{veyltrace:}\allowbreak\code{investigate}, the multi-turn mode with the verifier on, pre-registered on a 90-case subset with one case per cluster and three seeds and cut before it ran (\S\ref{sec:deviations}); and \code{agent-only:brief}, which ranks the same model's hypotheses in order with no verifier.
The proposer is Qwen3.5-9B~\cite{qwen35card} in a 4-bit quantisation, served locally; its GGUF weight digest is pinned in the configuration, an AI-arm run counts only on that digest (issue \#315, part of the engine-freeze commit), and scores published for the model are vendor-reported.
On RCAEval-C we add \code{naive-change}, which blames the service with the latest change before the alert.
The protocol also lists \code{prism-plain}, a re-implementation of PRISM from its paper, and RCAEval's other methods where they run; no pre-registered experiment configures any of them, and \code{prism-plain} was never built, so none of them is reported.
A cut arm is reported as not run, with its reason and the decision record that cut it.

\subsection{Alert and perturbation protocols}
\label{sec:protocols}

Every table uses the oracle-alert protocol unless stated; the detected-alert protocol is reported next to it, and a fault case with no detected breach counts as a miss and is reported as a separate count.
The perturbation protocols, all fixed a priori, are:
\begin{itemize}
\item \emph{onset shift}: $-120$, $-60$, $+60$ and $+120$\,s added to the oracle alert time ($\pm 30$\,s exploratory), because a two-minute shift took N-Sigma from 0.80 to 0.07 AC@1 on RE2 in a pre-registered preprint~\cite{hussain2026prereg};
\item \emph{telemetry ablation}: drop metrics, logs, traces or events, or keep metrics only; Sock Shop's lack of traces is a natural experiment;
\item \emph{leave-one-system-out calibration}: calibrate on two systems and test on the third, and calibrate on RE2 (OB and TT) and test on Nezha;
\item \emph{RCAEval-C}: a true change on the root at a uniform 0--120\,s before injection with probability $\pi \in \{0, 0.5, 1\}$, and Poisson decoy changes on other services at $\lambda \in \{0, 2, 6\}$ per hour from 30 minutes before to 5 minutes after injection, of kind deploy, configuration or flag; true and decoy changes share one schema, so the channel cannot tell them apart by format;
\item \emph{planted decoy proposal}: one fabricated proposal per case for a healthy service, with false claims;
\item \emph{proposal permutation}: the recorded proposals re-ordered with a seeded permutation and the verifier re-run from the cassette.
\end{itemize}
Every threshold and weight in the Reason engines was set a priori with a cited source; a value that had to be tuned was tuned only on RE1 or synthetic cases before the tag, and sensitivity sweeps are reported as curves, never used to pick a value.

\subsection{Splits and calibration}
\label{sec:splits}

A \emph{cluster} is a (system, root service, fault) triple: RCAEval's repetitions of a cluster share deployments and database state, so they are not independent and never straddle splits.
Within each (system, fault class) stratum, clusters are shuffled with a fixed seed and dealt alternately into folds A and B, and we cross-fit: calibrate on A and test on B, then the reverse, so every case gets exactly one test prediction from a calibration that shares no cluster with it.
Calibration is fitted separately for each AI arm and alert protocol, because $V$ differs between arms; perturbed runs reuse the files of their unperturbed protocol, so any coverage drift under perturbation shows.
In this paper only \code{veyltrace:off} under the oracle alert is calibrated: the experiments that would calibrate the \code{brief} arm were revised to run without it (\S\ref{sec:deviations}).
With the three development cases excluded, an RE2 fold holds about 134 cases, so $\hat{q}$ is about the 122nd smallest calibration score.

The protocol takes normal windows for \NOFAULT from RCAEval pre-injection segments and from one synthetic no-fault case used only for calibration; VeylLab's no-fault captures were pre-registered as a third source, but VeylLab is cut.
The pre-registered RE2 calibration configurations, frozen at the tag, add only the pre-injection segments, so the committed RE2 fits use those alone (\resnum{rq3-intervals/re2-oracle-rq3-off-v1}{literal_tau_sensitivity.held_out_fold.foldA.m_fitted} and \resnum{rq3-intervals/re2-oracle-rq3-off-v1}{literal_tau_sensitivity.held_out_fold.foldB.m_fitted} windows in the two fits).
\leadq{docs/04 §5.4 item 6 lists the synthetic no-fault case as a normal-window source, but \code{re2-oracle-rq3-v1} at \code{prereg-v1} sets \code{normal_windows:} \code{rcaeval_pre_injection} only, and no docs/04 §12 row covers the difference. Decide whether it needs a row.}
For the pre-injection segments, the oracle alert is moved 510\,s before injection, so the incident window ends 30\,s before the fault.
RE2 has only about 12 minutes of data before injection, so these windows keep about 1.5 minutes of baseline, and segments with less than 60\,s of baseline are dropped.
A segment may contain the tail of the previous case's fault, because RCAEval started the next case about 1.5 minutes after the previous fault with no baseline check (stated by the RCAEval author for RE2-TT; not documented for OB and SS); this biases $\tau_\text{nf}$ upwards, towards more \NOFAULT answers on faults, and we report it.
Normal windows follow the same clusters and folds, so the held-out false-alarm rate uses windows whose calibration fold excluded them.

\subsection{Metrics}
\label{sec:metrics}

Accuracy is AC@$k$ ($k = 1, 3, 5$), Avg@5 and MRR on the service ranking after RCAEval's coarse name transform, with fine-grained AC@$k$ on (service, indicator) and fault-type accuracy (not reported, \S\ref{sec:deviations}).
We decompose AC@1 as Retrieval@K $\times$ Rerank@1~\cite{decomprca2026} and also report decision-pool retrieval.
Chance@$k$ is $\min(k, n_i)/n_i$ averaged over cases with $n_i$ services, and lift is AC@$k$ divided by Chance@$k$.
Calibration is held-out coverage, its gap to $1-\alpha$, coverage given pool retrieval, and set size; abstention is the area under the risk--coverage curve (AURC) for $V$ and for $F$ (the committed summaries keep the areas, not the curves), selective accuracy among \st{CONFIRMED} and \st{LIKELY} verdicts, and the \NOFAULT false-alarm and wrong-\NOFAULT rates.
The LLM arms add proposer lift, proposal outcomes (not reported, \S\ref{sec:deviations}), decoy flips and permutation invariance; cost is wall time, peak memory and tokens per case; replay is the Tier-1 and Tier-2 rates.
Failed, timed-out and unranked runs count as misses, and every denominator is the full split.
AC@$k$ is computed on a ranking that the verifier writes for every status, so abstention cannot raise accuracy.
We do not use expected calibration error, because \sys outputs a set and a status, not a probability.

\subsection{Statistics}
\label{sec:stats}

Outcomes are paired by case, and clusters are the resampling unit: 90 on RE2 and about 30 on RE3.
Confidence intervals are 95\% percentile cluster-bootstrap intervals with 2,000 seeded resamples.
The primary test is a two-sided cluster sign-flip permutation test on the paired AC@1 difference with 10,000 seeded flips, with an exact McNemar test as a secondary check and Holm correction within the families \code{rq1} and \code{rq2}; non-inferiority (H1a) is decided by the unadjusted interval.
With about 30\% discordant cases, the minimum detectable difference is about 7 points on 270 cases and about 14 on 90, according to a pre-registered preprint~\cite{hussain2026prereg}, so per-system differences smaller than that are reported as ``not detected'', never as ``no difference''.
LLM arms use three seeds.
The protocol asks for each seed's AC@1 with its mean and standard deviation, but no committed summary holds them (\S\ref{sec:deviations}).
Paired tests use each case's mean hit over seeds.
Per-system results are primary; pooled results decide only H1b, H2a and H3a, whose unit is the RE2 calibration family, and other pooled values are descriptive; no test pools across datasets, because selecting one method across systems can pick the worse method for a given system~\cite{hu2026audit}.
Proportions use cluster-bootstrap intervals where clusters exist and exact binomial intervals otherwise.
The LLM arms follow the 2026 reporting guidelines for empirical software-engineering studies that involve LLMs~\cite{llmguidelines2026}: model, quantisation and GGUF weight digest (pinned and checked per run, issue \#315), runtime, decoding parameters, budgets, prompts and schemas, interaction logs, seeds, hardware, contamination and non-determinism are reported, with three exceptions (\S\ref{sec:deviations}): no committed file records the machine of the bench runs, the anonymisation probe that would test contamination was never configured, and per-seed values have no source.
H5's deterministic budget is read against a separate per-case sample on the slowest laptop, which records its machine (Table~\ref{tab:rq5laptop}), not against the bench runs; the sample covers a subset of each system's RE2 cases, not every case.

\paragraph{Logged deviations}
\begin{itemize}
\item \emph{Upstream reuse} (21 November 2026; ADR \code{20261121-ak-}\allowbreak\code{slate-method-}\allowbreak\code{upstream-reuse}). The single-ranker methods \code{causatrix:<ranker>} reuse the upstream steps of the \code{veyltrace:off} run of the same case and experiment, and run only FaultLoom and Causatrix, to save compute in the R-16 runs. Their time and memory cover two steps only, so the cost tables give them no cost. No RQ1 table had been read.
\item \emph{Tier-2 runtime} (22 November; ADR \code{20261122-ak-}\allowbreak\code{rq6-replay-results}). Tier-2 regeneration runs on the recording's own provider (Ollama, \code{qwen3.5:9b}, with the recorded run's resolved configuration) instead of \code{llama-server} with one slot and prompt caching off, because regenerating on another runtime would measure the runtime change, not regeneration. \item \emph{RQ3 without the proposer} (25 November; ADR \code{20261121-ak-}\allowbreak\code{r16-cut-list}, addendum of 25 November).
